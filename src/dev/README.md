# 회의록 초안 개발 화면

회의가 끝난 뒤 요약이 도착하고 초안이 만들어지기까지의 과정을 눈으로 확인하는 화면입니다. 회의 중에 프론트가 주고받은 API와 소켓 값도 함께 봅니다. (SCRUM-182)

개발 모드(`npm run dev`)에서만 켜집니다. 라우트와 기록 코드는 `import.meta.env.DEV` 조건 안에 있어서 배포용 빌드(`npm run build`)에는 들어가지 않습니다. 배포 사이트에서는 주소를 직접 입력해도 이 화면이 열리지 않습니다.

## 준비

프론트에 따로 세팅할 환경변수는 없습니다. 아래 두 가지만 띄우면 화면이 열립니다.

- 프론트 개발 서버 (`npm run dev`)
- 로컬 통합 환경 (`nineouting-infra/integration`). ai-service 8000번 포트는 기본 설정에서 열려 있습니다.

실제 요약과 초안까지 시험하려면 통합 환경의 ai-service에 AI 설정이 필요합니다. `nineouting-infra/integration/.env.example`을 `.env`로 복사해 값을 넣습니다. API 키는 `.env`에만 넣고 커밋하지 마세요.

| 설정 | 없을 때 |
|---|---|
| `LLM_PROVIDER`, `LLM_MODEL` | 회의 요약이 AI 대신 시험용 문구로 나옴 |
| `MINUTES_LLM_PROVIDER`, `MINUTES_LLM_MODEL` | 초안이 만들어지지 않음. ai-service 이미지에 따라 503 또는 `FAILED`로 끝남 |

이 설정을 넣으면 실제 AI를 호출하므로 비용이 들고, 회의 내용이 AI 서비스로 전송됩니다.

## 사용 방법

1. 시험할 회의를 만듭니다.
2. 새 탭에서 `http://localhost:5173/dev/minutes/{회의 번호}`를 엽니다.
3. 다른 탭에서 회의를 시작하고 끝까지 진행합니다.
4. 회의가 끝나면 회의록 양식을 고릅니다.
5. 개발 화면에서 진행 단계를 봅니다. 필요하면 `초안 재요청`을 누릅니다.

API·소켓 기록은 개발 화면을 열어 둔 동안의 값만 받습니다. 회의를 시작하기 전에 열어 두세요.

## 화면 구성

위쪽은 회의 중에, 아래쪽은 회의가 끝난 뒤에 주로 봅니다.

```text
API·소켓 기록                      | ai-service (로컬 전용)
--------------------------------------------------------
회의 요약         | 칸별 결과      | 변경 기록
초안 (재요청 버튼) |                |
```

| 영역 | 보여 주는 값 |
|---|---|
| 머리글 오른쪽 단계 | 회의록 없음, 요약 대기, 초안 요청 가능, 초안 생성 중, 초안 완료, 초안 실패 |
| API·소켓 기록 | 다른 탭의 프론트가 주고받은 값. 목록에서 고르면 옆에 고정해서 보여 줌 |
| ai-service (로컬 전용) | 회의 상태, 대기열, 작업별 AI 호출 수 |
| 회의 요약 | `final` 여부와 `todaySummary` 원문 |
| 초안 | `draftStatus`, `draftError`, 재요청 버튼 |
| 칸별 결과 | 회의록 칸별 글자 수와 내용 |
| 변경 기록 | 3초마다 조회해서 값이 달라진 항목 |

기록은 메모리에만 있어서 새로고침하면 사라집니다. 남기려면 변경 기록의 `JSON 내려받기`를 누르세요. API·소켓 기록도 같은 파일에 들어갑니다.

## ai-service 값 읽는 법

| 값 | 뜻 |
|---|---|
| `queued` | 회의별 대기열에서 아직 시작하지 못한 작업 수. 일꾼이 처리 중인 작업은 빠짐 |
| `분류 대기 줄` | 안건 분류를 기다리는 전사 줄 수 |
| 표의 `호출` | 그 회의에서 작업별로 쌓인 누적 호출 수. 재시도도 포함 |
| 표의 `3초간` | 직전 조회보다 늘어난 호출 수. 실제 간격은 3초에 응답 시간을 더한 값 |

`queued`가 계속 늘면 처리가 들어오는 속도를 못 따라간다는 뜻입니다. 회의 종료 작업은 대기열 맨 뒤에 들어가므로, 앞에 밀린 작업이 끝나야 시작됩니다.

## 알아둘 점

- **지금 처리 중인 작업은 알 수 없습니다.** ai-service가 이 값을 주지 않아서, 호출이 늘어난 줄로 짐작합니다.
- **초안 호출은 작업 표에 없습니다.** 회의 상태에 포함되지 않습니다.
- **자동 초안 요청의 실패는 화면에 나오지 않습니다.** 이 실패는 `draftStatus`에 저장되지 않고 서버 로그에만 남습니다.
- **재요청은 빈 칸만 채웁니다.** 글이 있는 칸은 그대로라서, 재요청이 성공해도 칸별 결과가 바뀌지 않을 수 있습니다.
- **초안 생성 중에 재요청하면 앞 요청의 결과가 버려집니다.** 그래서 이때는 확인 창이 뜹니다.
- **ai-service를 재시작하면 카드에 404가 나옵니다.** 회의 상태를 메모리에만 보관하기 때문입니다. 고장이 아니고, DB의 회의와 회의록은 그대로입니다.

## ai-service 연결

ai-service 상태는 게이트웨이를 거치지 않고 `vite.config.ts`의 프록시로 직접 조회합니다. 이 프록시는 `/__ai/meetings/{회의 번호}/status` 경로만 엽니다.

기본 주소는 `http://localhost:8000`입니다. ai-service가 다른 주소에 있을 때만 개발 서버를 띄울 때 `AI_PROXY_TARGET`을 넣어 줍니다. 시작할 때 읽는 값이라 바꾸면 개발 서버를 다시 띄워야 합니다.

```bash
AI_PROXY_TARGET=http://localhost:9000 npm run dev
```
